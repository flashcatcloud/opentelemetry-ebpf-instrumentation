# Oracle Tuxedo and OCI instrumentation

OBI instruments dynamically linked Oracle Tuxedo ATMI and Oracle Call Interface (OCI) clients
and servers with uprobes. The instrumentation is selected automatically when a discovered process
maps `libtux.so` or `libclntsh.so`.

## Tuxedo

The Tuxedo client instrumentation observes synchronous `tpcall` calls and asynchronous
`tpacall`/`tpgetrply` calls. It reports RPC client spans with:

- `rpc.system.name=tuxedo`
- `rpc.method` set to the ATMI service name

Immediate ATMI failures mark the span as failed. Cross-process trace-context propagation is not
currently supported because it requires an application-compatible propagation field in the
Tuxedo typed buffer.

For Tuxedo servers generated by `buildserver`, OBI attaches to an exported `RUNSERVER` service
routine in the application executable. It reads the invoked service from `TPSVCINFO.name`, starts
an RPC server span, and finishes it at `tpreturn` or `tpforward`. The active server span is made
available to OCI and other client probes on the same worker thread. Multiple advertised Tuxedo
services may map to the same routine; their individual names remain visible through `rpc.method`.

Tuxedo does not define a standard W3C Trace Context carrier. The server span therefore joins an
upstream trace only when OBI can correlate an existing request on the same worker; otherwise it
starts a new trace.

## Oracle OCI

The OCI instrumentation observes `OCIServerAttach`, `OCIAttrSet`, `OCIServerDetach`,
`OCIHandleFree`, `OCIStmtPrepare`, `OCIStmtPrepare2`, `OCIStmtExecute`, and `OCIStmtRelease`.
Prepared SQL is associated with the OCI statement handle and emitted when the statement executes.
The service-context-to-server association supplies the connection string to the SQL span. Easy
Connect strings and full descriptors populate `server.address`, `server.port`, and `db.namespace`.
It reports database client spans with `db.system.name=oracle.db`.

SQL text follows the existing database trace attribute selection. OBI reads at most 499 bytes of
the statement and does not parse Oracle TNS traffic. A TNS alias is reported as the server address
unless it can be resolved outside OCI. Connections established before OBI attached do not expose
their original `OCIServerAttach` string until they reconnect. Statements executed without an
observed prepare call still produce an Oracle database span without query details.

Both instrumentations require dynamically linked, exported symbols with the standard C ABI.
